# Slack 報告メッセージ生成 (上司報告寄り)

直前の作業やユーザーが指定した内容を、Slack スレッド形式の報告メッセージに変換する。

## 文体ベース

`../slack-zakki/SKILL.md` の文体ルールを基本とする。以下の点だけ上書き:

- **トーン**: 丁寧だが堅すぎない。報告だけど共有感がある文体
- **敬語レベル**: 「〜いただけますでしょうか」「〜いただきます」「〜お願いできますか」程度。二重敬語や「〜させていただければ幸いです」は硬すぎ
- **絵文字**: `:bow:` 程度は OK。乱用しない

## 構造（スレッド形式）

必ず以下の形式で出力する:

### 1. 親メッセージ（短く）
```
XXX さん
お疲れさまです。[機能名 / タスク名]（対象案件があればチケットリンク）の件、[状況サマリ 1 文]。スレッドに続けます:bow:
```

### 2. スレッド（トピック別に分割）
各トピックは `---` で区切り、番号付き見出しで始める。1 トピック = 1 つの確認事項や報告。

```
---

1. [トピック名]
[内容。2-4 文で短く]
```

### 3. クロージング
最後のトピックに確認依頼・次のアクション・質問を含める。

## ルール

- 1 トピック = 1 つの話題。混ぜない
- 技術詳細は「PR に貼る予定です」「詳細は PR で」で省略。Slack で長々書かない
- 添付物（スクショ、動画）がある場合はトピック内で言及し、メッセージの後に添付
- チケット/課題 URL がある場合のみリンクを重ねる。無ければ機能名・タスク名主体で十分
- `【】` は使わない
- ※ より雑談寄り（口語・共有感）にしたい場合は `../slack-zakki/SKILL.md`、
  返信 draft の反復推敲用途なら `../slack-reply-polish/SKILL.md`。
  本 skill は上司への報告寄り（丁寧だが堅すぎない）

## 手順

1. `$ARGUMENTS` があればその内容を元にする。なければ直前の会話コンテキストから作業内容を把握する
2. トピックを洗い出し、スレッド分割を決める
3. 上記の構造に従ってメッセージを生成
4. 各メッセージをコードブロックで囲んでコピペしやすく出力
5. 添付物がある場合は `（スクショ添付）` `（動画添付）` をメッセージ間に挿入
