## Round 2: 正確性検証

### tail --pid の技術的正確性

| 主張 | 検証方法 | 結果 | 判定 |
|------|----------|------|------|
| `tail --pid=<PID> -f /dev/null` で PID 監視可能 | 実機テスト (Linux 6.8.0) | 正常動作。PID 存在中は待機、PID 終了後に exit | PASS |
| PID 既終了時は即座に終了 | 実機テスト (PID=999999) | 即座に exit (exit code 0) | PASS |
| PID 不存在でもエラーにならない | 実機テスト | エラーなし、即 exit | PASS |
| shell `&` vs `run_in_background` の違い | Claude Code tool spec 確認 | 正確。shell `&` は task notification に登録されない | PASS |

### man page との整合性

`man tail` 記載: `--pid=PID: with -f, terminate after process ID, PID dies`

- **ポーリング間隔**: `--sleep-interval` デフォルト 1.0 秒。inotify 使用時は `--pid=P` で少なくとも N 秒ごとにチェック。SKILL.md には記載なし（実用上問題ない遅延だが、sub-second 精度が必要なケースでは影響あり）

### エッジケース分析

| エッジケース | SKILL.md 記載 | 実際の挙動 | 判定 |
|-------------|--------------|-----------|------|
| PID 既終了 | 記載あり (L68) | 即 exit、正確 | PASS |
| PID 不存在 | 記載あり (L68) | 即 exit、正確 | PASS |
| セッション切断 | 記載あり (L69) | tail 残存、通知不可。正確 | PASS |
| **ゾンビプロセス** | **未記載** | `kill(pid,0)` は zombie に対して成功を返すため、tail は終了を検知**しない**。永久に待機し続ける | **未カバー** |
| **PID 再利用** | **未記載** | pid_max=4194304 (このシステム)。長時間監視で別プロセスに PID が再割当された場合、誤って待ち続ける。実用上はリスク極小 | **未カバー (低リスク)** |
| **macOS 非対応** | **未記載** | BSD tail は `--pid` 非対応。GNU tail (Linux) 専用 | **未カバー (環境固定なので低リスク)** |

### R2 発見事項

1. **ゾンビプロセス**: `tail --pid` は zombie を「生存中」と判定する。nohup ジョブでは通常発生しないが、親プロセスが `wait()` しない場合に問題となる。注意事項に 1 行追加が望ましい
2. **PID 再利用**: pid_max=4194304 かつ長時間ジョブ用途では実質リスクゼロ。記載不要
3. **macOS 非対応**: 環境が Linux 固定のため実害なし。ただし他ユーザーが流用する可能性を考慮すると、前提条件として 1 行記載が親切
4. **ポーリング遅延**: 最大 1 秒の検知遅延があるが、長時間ジョブ監視用途では無視できる

### R2 判定: PASS (ゾンビに関する注意事項の追加を推奨)
