# スコープ外項目の振り直し

対象の plan.md: $ARGUMENTS

## 完了条件

**スコープ外セクションの全項目が、以下のいずれかの状態であること:**

- `→ **NNN-taskname**` 形式で具体タスク ID を指定
- `→ 対応不要（理由: ...）` 形式で明確な根拠あり
- `→ NNN-taskname で自然消滅（根拠: ...）` 形式で解消方針を明記

**以下は不合格（1つでもあれば完了不可）:**
- タスク ID なし（例: `管理画面は本タスクのスコープ外`）
- 曖昧な追跡先（例: `別タスクで対応`、`将来対応`、`FE移行時`）
- 完了済みタスクへの追跡

## フロー

### Step 1: スコープ外項目の全数棚卸し

完了タスクの plan.md「スコープ外」セクション + 各 Phase の report.md「スコープ外」セクションを精読し、**全項目**をリストアップする。

各項目を以下に分類:

| 分類 | 状態 | 対応 |
|------|------|------|
| 追跡先が正確 | 具体タスク ID あり、そのタスクが未完了 | 検証のみ |
| 追跡先が不正確 | 完了済みタスクを指している、スコープに含まれていない | 再割当 |
| 追跡先が未定義 | 「別タスク」「機能変更」等の曖昧な記述 | 割当先を確定 |
| 追跡先がない | タスク ID も曖昧記述もなく、ただ「スコープ外」とだけ記載 | 割当先を確定 |
| 自然消滅 | 後続タスクで構造的に解消される | 解消方針を明記 |
| 対応不要 | 技術的に不要、影響なし | 理由を明記 |

**全項目を振り直し結果表に記載すること。一部だけ処理して残りを放置してはならない。**

### Step 1.5: 追跡先候補タスクの完了状態を一括確認

**振り先を決める前に**、候補となるタスクの Phase status を確認する:

```bash
for dir in $ORDER/NNN-*/; do
  task=$(basename "$dir")
  done_count=$(grep -c 'done' "$dir/plan.md" 2>/dev/null || echo 0)
  total=$(grep -c 'pending\|done\|in.progress' "$dir/plan.md" 2>/dev/null || echo 0)
  echo "$task: $done_count/$total phases done"
done
```

**全 Phase が done のタスク = 完了済み → 振り先として使用禁止。**

### Step 2: 追跡先の検証・確定

**全項目について**（1つも飛ばさない）:

1. **具体内容を特定**: 完了タスクの work/ や appendix/ から発見経緯・詳細を探す
2. **追跡先候補を検討**:
   - 既存タスクのスコープに含まれるか（plan.md を確認）
   - **追跡先タスクが完了済みでないことを確認**（Step 1.5 の結果を参照）
   - 後続タスクで自然消滅するか（アーキテクチャ変更等）
   - 新規タスクが必要か
3. **判定結果を記録**: 項目ごとに根拠付きで追跡先を確定

### Step 3: 追跡先への明示的追記

**これが最も重要なステップ。** 元タスクは二度と開かないため、情報を追跡先に移す。

既存タスクに振る場合、追跡先の plan.md に引き継ぎセクションを追記:

```markdown
## {元タスクID} からの引き継ぎ

- {具体的な項目}: {対応方針の簡潔な説明}
```

新規タスクが必要な場合は、ユーザーに提案する（勝手に作らない）。

### Step 4: 元タスクの plan.md 更新

スコープ外セクションの**全項目**を、確定した追跡先に書き換える:

```markdown
## スコープ外
- {項目} → **NNN-taskname** で対応
- {項目} → **NNN-taskname** で自然消滅（根拠: ...）
- {項目} → 対応不要（理由: ...）
```

### Step 5: 全数検証

振り直し結果表の行数とスコープ外セクションの項目数が一致することを確認。

- [ ] **全項目処理済み**: 棚卸しした項目数 = 振り直し結果表の行数 = plan.md スコープ外の項目数
- [ ] **曖昧ゼロ**: 「別タスク」「機能変更」「将来対応」等の曖昧な追跡先がゼロ
- [ ] **追跡先なしゼロ**: タスク ID も「対応不要」理由もない項目がゼロ
- [ ] **誤追跡ゼロ**: 完了済みタスクへの追跡がゼロ
- [ ] **引き継ぎ追記済み**: 追跡先タスクの plan.md に引き継ぎセクションが追記されている
- [ ] **自然消滅の根拠あり**: 「自然消滅」項目に解消の根拠が記載されている

## テンプレート: 振り直し結果表

```markdown
| # | 項目 | 旧追跡先 | 判定 | 新追跡先 | 根拠 |
|---|------|---------|------|---------|------|
| 1 | {項目} | {旧} | 再割当/自然消滅/対応不要/正確 | {新} | {理由} |
```

## 実例

003-codebase-cleanup で発見された5項目の振り直し:

| 項目 | 旧追跡先 | 新追跡先 |
|------|---------|---------|
| セキュリティヘッダー/LOGGING/CORS | 001（完了済み） | Wave 3（006+）Django廃止で自然消滅 |
| NGINX設定変更 | 別タスク（未定義） | 004-filebrowser-separation |
| TODOコメント（authCompat.ts） | 機能変更（未定義） | 007-auth-migration |
| TODOコメント（scroll.ts） | 機能変更（未定義） | 009-page-migration |
| django-redis除去 | 別タスク | 006+ PG移行で自然消滅 |

追跡先 004, 007, 009 の plan.md に「003からの引き継ぎ」セクションを追記済み。
5/5 全項目処理済み。
