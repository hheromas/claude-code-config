# slack-report - Slack報告文ジェネレーター

直前の作業やユーザーが指定した内容を、Slackの運用チャンネル向けの雑談風メッセージに変換する。

## 文体ルール

### トーン
- **雑談くらいの湿度**。報告ではなく共有
- 口語体：「〜ぽい」「〜だったので」「〜してます」「〜かも」
- 短く。ダラダラ書かない

### 必ず含める要素
1. **何を観測したか**（具体的な数字・事実）
2. **なぜそう考えたか**（推論の根拠 — 調べた感・考えてる感を出す）
3. **何をしたか**（対応内容）
4. 対象の具体名（VM ID、ホスト名、サービス名など）
5. 問題時の連絡先 or ロールバック可能な旨

### 絶対にやらないこと
- 「【お知らせ】」「■ 原因」のような形式的な見出し
- 箇条書きの羅列（対象リストは例外的にOK）
- 長い技術説明（聞かれたら別スレで答える前提）
- 「実施しました」「確認済みです」のような硬い敬体
- 絵文字の乱用

### 構造
```
[何が起きてた/何をしたかの一文] → [調べたら〜で/見たら〜で] → [こう考えて/こう判断して] → [こうしました]

対象: [具体的なリスト]

[何かあったら言って的なクロージング]
```

## 良い例

```
ops.jnとzabbixが昨日フリーズしてた件、調べたらgimmokuseiのNVMeで断続的にI/Oタイムアウトが起きてて、それをきっかけにLSI SCSIコントローラのDMA処理がデッドロックしてVMが固まったっぽい。gimmokuseiで動いてる19台中この2台だけ古いLSI使ってて、他のvirtio-scsi勢は全部無事だったので、virtio-scsiに変更しました。ついでにbitwardenも同じ設定だったので一緒に変えてます。

対象: VM 104 (ops.jn), VM 103 (bitwarden), VM 117 (zabbix)

なんかおかしかったらすぐ戻せるので言ってください〜
```

## 手順

1. `$ARGUMENTS` があればその内容を元にする。なければ直前の会話コンテキストから作業内容を把握する
2. 上記の文体ルールに従ってメッセージを生成
3. コードブロックで囲んでコピペしやすく出力
