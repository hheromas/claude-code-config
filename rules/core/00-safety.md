# 安全性ルール (3-Tier Permission Model)

操作の安全性に基づく 3 段階の権限分類。

---

## Tier 1: 許可不要 (Always Allowed)

確認なしで即座に実行してよい操作:

- **読み取り専用**: `git status`, `git diff`, `git log`, ファイル読み取り
- **静的解析/フォーマット**: `ruff format`, `ruff check`, `pyright`, `shellcheck`
- **テスト実行**: `pytest`, `bandit`

## Tier 2: 要確認 (Ask Before)

実行前にユーザーの明示的な承認を得る操作:

- 現在のタスクスコープ外のファイル書き込み/編集
- `git push`, `git merge`
- 外部 API 呼び出し
- パッケージのインストール (`pip install`, `npm install` 等)

## Tier 3: 禁止 (Never)

絶対的禁止事項。理由の如何を問わず、以下の行為は絶対に行わない。

## 禁止事項

- **NEVER:** 明確な承認プロセスを経ずに、本番環境のデータを変更または削除すること
- **NEVER:** API キー、パスワード、その他のシークレット情報をコード内にハードコーディングすること
- **NEVER:** テストや静的解析でエラーが検出された状態でコードをコミットすること
- **NEVER:** `main`や`master`といった保護されたブランチに直接プッシュすること
- **NEVER:** 認証・認可に関わるコードの変更に際し、セキュリティレビューのプロセスを省略すること

## 拒否時の対応

これらの行為を指示された場合は、安全上のリスクを指摘し、実行を拒否する。
